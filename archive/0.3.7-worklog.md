# Debris Y compression

## Previous-task review

The 0.3.4 work landed as a pure view rule. This milestone was reviewed against
the wild-mine draft (`0.4.0`), which asks for the debris factor to be available
in every mode before that mode exists, and against the current floor code: the
tile height was a single constant, so the pile shape could not be chosen at all,
while every consumer already converted cells to metres through that same
constant. One live value therefore moves the whole floor at once, which is why
this is a setting rather than a second debris model.

## Implementation

- `js/ceiling.js`: `floorCompression` (default 4) with `setFloorCompression`
  (rounded to half steps, clamped to `floorCompressionMin` 1 …
  `floorCompressionMax` 8, a nonsense value back to 4) and `floorCellHeightNow()`.
  Every reader of the old constant — deposit, garage grader cut, road-grader
  settlement, floor harvest, tile drawing — now asks for the live value, and
  `state.floorCellHeight` became a getter beside `state.floorCompression`. The
  setter is exported on `SteamCeiling` and in `state`'s numeric limits.
- `js/ceiling.js`: `generateTestRock` now clears `floorPiles` and `floorValues`
  like `reset` does. It builds a fresh run without going through `reset`, so it
  was the one entry point that carried the previous floor into the new rock.
- `index.html`, `js/main.js`, `js/main_input.js`: `DEBRIS` select (1, 2, 3, 4 =
  the current 4:1 tile and the default, 6, 8) with its help mark and change
  handler; the handler marks the scene and never touches the world.
- `js/help.js`: `debris` topic (layer thickness is the cell width divided by the
  factor, the cap, and that the material and its value never change).

## Decisions

- **One factor, not one per pile.** The floor is one heightmap, so a second
  per-column factor would only be a drawing trick with no owner. The setting is
  a chamber rule, like the rock shape and the ground bounce, and survives New
  game.
- **No re-cutting on change.** Switching 4 → 1 keeps each column's metres and
  value and simply draws them as one tall layer. Re-cutting buckets would either
  lose or create material, and would make the setting a command rather than a
  view.
- **The cap stays in metres.** `pileLimit` is 0.7 m of *drawn* height, so a
  flatter setting legitimately holds more cells. That is the one place where the
  setting changes gameplay-adjacent numbers, and it is the existing rule: the
  cap is about how high a pile may stand, not how much it may contain.

## Validation

- `node --test experiments/*.test.js`: 292 / 292 pass.
- New `experiments/debris-compression.test.js` (5 cases): clamping and half-step
  rounding with 4:1 as the reference; the same cells and value at 1, 2, 4 and 8
  with only the drawn profile changing; the tile ratio equals the factor and the
  layer count follows it (including the part tile that closes a crest);
  `harvest` takes the same four cells whatever a layer is drawn as, and the
  pay-share of the take is exact; switching moves no bucket, and both
  `reset` and `generateTestRock` keep the choice while clearing the floor.
- New interface case: the select drives `SteamCeiling.setFloorCompression`, a
  filled floor redraws as square layers at 1, the material and funds do not
  move, and New game keeps the setting with a clear floor.
- A sixth case settles a 0.5 m rubble bed under the platform at 4, 2, 1 and 8:
  the hull rides the pile at 0.500 m in every setting, `floorAt` agrees and the
  balance is exact, so the setting never changes where the ground is, only how
  tall it is drawn.
- A settle probe at 1 / 2 / 4 / 8 confirmed the drawn height scales exactly with
  the factor while cargo, lost cells and total pile value stay identical
  (1: 9.325 m, 2: 5.0625 m, 4: 2.5313 m, 8: 1.2656 m for the same fall).
- `node --check` on every changed script; `git diff --check` clean.
- Real Chromium: `DEBRIS` moves `floorCellHeight` from 0.03125 to 0.125 going to
  1 (`floorCompression` 4 → 1), the
  select and both new system-bar labels stay inside the viewport from 390 px to

## Pitfalls found

- `ceiling.floorAt` reads the smoothed `floorHeight` profile, which only
  `updateFloor` rewrites; `drawFloor` calls it, but a test that fills
  `floorPiles` by hand must draw (or call the same path) before querying the
  surface. The rock has the same relationship between `firstRow` and
  `heightmap`.
- `harvest` steps columns by whole cells of capacity, so four cells of capacity
  over two-layer columns takes two columns completely, not four partially. Read
  the hopper limit before writing the expectation.
- `drawFloor`'s inner loop starts `y` at 0 and steps by the tile height, so a
  float residue can add one thin extra tile past the last whole layer. Assert on
  `ceil(pile / tile)` and on the part tile closing the crest, not on a floor.
