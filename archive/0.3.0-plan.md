# 0.3.0 — Platform render stabilization

Status: implemented for render path; see `archive/0.3.0-worklog.md`.

## Goal

Both platforms must be drawn by one routine with identical geometry. The only
difference between the active and the inactive platform is a dimmed colour.
Switching the active player must move the dim immediately, without accumulated
darkening, and no bounding box may be part of the design.

## Decisions

- Replace the separate second-platform rendering with a single `renderPlatform(context, player, rigMachinery, isActive)`.
- Both platforms share one model, one set of dimensions, one shape, one detail
  set and one coordinate transform.
- Colour is derived every frame from activity:
  `renderedColor = isActive ? baseColor : dim(baseColor)`.
- The dim factor is applied to the whole platform at once through canvas
  alpha, including blade, load heap, wheels and any rig machinery overlay.
- Dim state is never stored in the platform object or in a cache.
- `players.active` is the single source of truth; render reads it on every frame.
- The active-platform accent outline / bounding box is removed. A future
  debug mode may draw bounds, but it must be visually distinct from the design.
- Multi-switching must be idempotent: dimming never compounds.

## Suggested implementation

- `js/players.js`: `renderPlatform` as the only body draw path; `draw` calls
  it for every player with `isActive = player === players[active]`.
- Expose `renderPlatform` from `SteamPlayers`.
- Keep geometry helpers (`profileAt`, `surfaceAt`, `halfWidth`) shared and
  unchanged.
- Remove any leftover second-platform primitives, separate geometry and stale
  colour caches.

## Acceptance

- Geometry of both platforms is identical in tests and by construction.
- Active platform uses base colours; inactive uses their dimmed derivatives.
- After `setActive`, colours swap on the next draw.
- Repeated switching does not accumulate dimming.
- No bounding box is drawn in normal mode.
