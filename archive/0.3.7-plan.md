# 0.3.7 — Debris Y compression

## Goal

One setting that decides how tall a fallen-soil layer is: the same amount of
rubble can lie flat as a thin sheet or stand as a deep pile. Today the debris
heightmap is hard-wired to a 4:1 tile (`floorCellHeight = cell / 4`), so the
only pile shape the game can make is the one it ships with. The wild-mine draft
(`0.4.0`) needs a flatter default of 1.5, so the setting lands here, available in
every mode, before that mode exists.

## Decisions

- The setting is `DEBRIS` in the system bar, a Y-compression factor from 1 to 8
  in half steps, **4 = today's 4:1 tile** as the default and the reference for
  every existing number. `floorCellHeight = cell / compression`, so 1 makes a
  square tile (a loose 1:1 rubble layer) and 8 the flattest sheet.
- It scales the *drawing of height*, not the quantity of material. Every
  consumer of `floorCellHeight` (deposit, garage grader, blade, harvest, tile
  drawing) already converts between cells and metres through it, so one number
  moves the whole system together and the number of cargo cells a pile holds is
  unchanged by the setting.
- `pileLimit` (0.7 m) stays the cap on the *drawn* height, exactly as it is
  today: a flatter setting simply lets more cells fit under the same cap before
  the rest is booked as lost, and a deeper one caps sooner.
- The energy ledger is untouched: `floorPiles` and `floorValues` are metres and
  credits, and the setting only changes the tile that a metre is drawn as.
- Switching the setting is a live view change: no cell moves, no debris is
  dropped, and the settled pile under each column is simply drawn taller or
  flatter. Buckets in a pile are not re-cut, so a half-cut column at 4 stays a
  half-cut column at 1.
- A finished session's debris is world state, so a New game resets the piles;
  the *setting* is a chamber rule like the rock shape, the ball arrangement and
  the ground bounce, and survives New game.

## Suggested implementation

- `js/ceiling.js`: `floorCompression` (default 4) with `setFloorCompression` and
  `floorCellHeightNow()`; replace the `const floorCellHeight` readers with the
  live value. Also clear the floor in `generateTestRock`, which builds a fresh
  run without going through `reset` and would otherwise carry the old pile into
  test rock.
- `index.html`: `DEBRIS <select id="debris-compression">` with 1, 2, 3, 4, 6, 8
  (`4 · current 4:1 tile` selected by default), a help mark, and the topic.
  The setter is also exposed on `SteamCeiling` so a mode can pick its own
  default (`0.4.0` wants 1.5 for the wild mine).
- `js/help.js`: `debris` topic — what the factor does to the picture, what it
  never does to the ledger, and that it also changes how many cells fit under
  the 0.7 m cap.
- `js/main.js` / `js/main_input.js`: id binding and change handler (marks the
  scene; never touches the world).

## Acceptance

- A deposit of *n* cells adds `n * cell / compression` metres of pile at any
  setting, and the drawn tile count and height both follow.
- The grade, blade and harvest paths convert through the same value, so a
  sweep at 1 and at 8 removes the same one-tile layer and pays the same share.
- Changing the setting never changes `floorPiles`, `floorValues`, cargo, funds
  or the energy balance, and survives New game.
- `node --test experiments/*.test.js` passes; the existing 4:1 assertions are
  written against the default and stay true.
