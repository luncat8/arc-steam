# 0.3.12 — Testing & Development Optimization Plan

## Purpose

Record measured wall-clock bottlenecks observed while running the 0.3.12
progression-income sweep, wet-solver microbenchmarks, and affected test suites,
and lay out concrete ways to speed up both test runs and day-to-day simulation
development without running or touching unrelated suites.

## Optimization Plan for Testing & Development

### 1. Throttle / cache `autopilot` multi-bounce prediction (`ballistics2`)
- **Problem**: `autopilot.update` calls `prediction` every 240 Hz tick, costing
  `~1.0–1.4 ms/step` when `ballistics2` is active (73% of Stage 3 CPU).
- **Plan**:
  - Invalidate and recompute the full multi-bounce trace only on discrete state
    changes (ball bounce off rock/wall/deck/floor, piston angle change, ball
    release/capture, or a 15–30 Hz fallback cadence) rather than every 240 Hz
    step.
  - Expected impact: **3–4× faster** Stage 3 simulation and multi-minute sweeps
    (`130 s` → `~35–45 s` per 240 s seed), plus lower browser CPU in late game.

### 2. Full state save / load for instant test & dev snapshots
- **Problem**: Even though `ceiling.reset()` only takes `23–99 ms`, tests and
  developers waste seconds to minutes simulating warm-up states (e.g. filling
  a hopper with sand/stone in `interface.test.js` #48 taking `14.9 s`, or
  reaching Stage 2/3 organically). Save/load is also an open requirement in
  `0.3.8-plan.md`.
- **Plan**:
  - Implement versioned `saveState()` / `loadState(snapshot)` across `world`,
    `ceiling`, `water`, `equipment`, `research`, `rockets`, `sandblaster`,
    `players`, and `autopilot` (also useful for pre-generated slow map/chamber
    fixtures).
  - Pre-bake or snapshot warm-up fixtures (e.g. mid-shift wet chamber, loaded
    sand hopper, Stage 3 rig) so slow setup tests load in `<10 ms` instead of
    stepping thousands of warm-up frames.

### 3. Split fast unit/UI checks from slow multi-second physics tests
- **Problem**: `interface.test.js` takes `36.4 s` largely because 7 simulation-heavy
  or real-timer subtests (#48, #49, #16, #53, #29, #47, #26) sit inside the
  same file as 47 fast (`<100 ms`) DOM/state tests.
- **Plan**:
  - Extract slow warm-up / multi-second integration subtests (or tag them with
    a naming prefix such as `[slow]` and move them to `*.slow.test.js` /
    `experiments/interface-tools.test.js`) so the default fast edit-verify loop
    runs in **<3–5 s** instead of `36+ s`.
  - Keep slow tests runnable on demand (`node --test experiments/*.slow.test.js`
    or before milestone completion / when editing the specific subsystem).
  - Replace wall-clock `setTimeout` delays in DOM hold tests (#29, `2.1 s`) with
    configurable/fake timers or injected `now()` hooks where safe.

### 4. Further `water.js` floor-puddle & sweep optimizations
- **Problem**: `floor puddle` still spends `~110 µs/step` largely rebuilding
  `solidMask` across rock rows `45..59` every step even when no droplets are
  airborne and `wetRowMax < 45`.
- **Plan**:
  - Track `hasFlyingDroplets` in `water.js` and skip rock-layer `solidMask`
    rebuilds while `!hasFlyingDroplets && wetRowMax < rockStartRow`, cutting
    idle floor-puddle overhead further.
  - Keep `worker_threads` seed parallelism and single-pass multi-checkpoint
    snapshots (`240s`/`480s`/`720s` in one run) across all `experiments/*.cjs`
    sweeps.
